## 3. 转换管线（Phase XX 态）

```
EDF/DSN 输入
  ↓ EDIFParser（页面结构 24 页 / 3023 实例）
  ↓ ComponentCatalog（CrossRef CSV：entire.csv 完整版 914 条）
  ↓ MatcherPipeline（两阶段匹配：TypeHypothesis → CandidatePool → Passive/ActiveMatcher）
  ↓ ConnectivityModelBuilder（DesignConnectivity：cells/nets/instances/pins）
  ↓ ConversionEngine.convert
  │   ├── P0-D2 页面归属（★ 用 CSV page_name 放置实例——QA-3 修复点）
  │   ├── 匹配 + placeholder/mock 判定（★ _needs_placeholder：mock_all 优先）
  │   ├── Pass 1：body_coords → OverlapResolver（★ 接线，passive+connector 微调）→ _compute_pin_geometry（pin_coords/LASTPIN 同源）
  │   ├── 路由（wire_layout + detour_router）+ wire_simplify（可选）+ text_layout
  │   ├── CSA 生成（FORCEADD/LASTPIN/$LOCATION/PACKAGE_TYPE 注入/xcon XML 转义/origin 库）
  │   └── 输出：24×csa/csv/cpc + con/xcon + cpm + tag + temp_lib(100 cell) + origin + test_spn
```

**关键数据流**（多次踩坑后固化）：
- **引脚坐标单源**：`_compute_pin_geometry` 的 `pin_coords` 同时喂 LASTPIN 和 WIRE 端点（Cadence 唯一连接规则——坐标必须重合）。
- **OverlapResolver 必须在 pin_coords 之前**：body 位移后 pin/LASTPIN/WIRE 全部用新 body 重算（否则 LASTPIN miss → 543 回归）。
- **mock 坐标 50 栅格**：distribute 全部对齐 50 倍数（Cadence WIRE 端点栅格约束，off-grid 会断连）。

## 5. Phase XIX：Cadence 16.6 全报错根因闭环

### 5.1 SPCOCD-553（xcon 语法错误）——QA-4

**用户报错**：
```
ERROR(SPCOCD-553): connectivity server error: error while loading schema file '5015.xcon' because of syntax error
ERROR(SPCOCD-553): could not find connectivity information for block '5015' in library '5015_lib'
```

**根因**：`.xcon` 是 **XML**（Cadence CS Schema）；MARK 元件自动网络名 `unnamed_22_mark_i73_&1` 含**裸 `&` 未转义** → XML not well-formed（实测 line 3101）→ connectivity server 加载失败 → 第二个错误是连锁。

**修复**：`xcon_writer.py` 新增 `_xml()`（& → &amp; 等），覆盖 header/cells/nets/instances/netScope/页面引用**全部插值点**。

**官方资料**（WebSearch 确认）：SPCOCD-553 是 Cadence 16.6 **已知 bug**，SPB16.60.074 Hotfix 补丁清单含 `1604223 CONCEPT_HDL CORE ERROR: SPCOCD-553`。**用户需确认已装最新 Hotfix**（即使 xcon 语法正确也可能复现）。

**验证**：4 版本 5015.xcon 全部 XML 可解析（schemaVersion 16.6、nets=1511、instances=1848、pages=24）、裸 & = 0；+2 防回归测试。

### 5.2 SPCOCN-1158（"pin property not preceded by connection"）——三轮根因

用户实测全部 _PH 芯片图标消失，报错定位到 symbol.css **line 11**。

| 轮次 | 根因（grep 全库实锤） | 修复 |
|------|----------------------|------|
| ① | C 指令/X PIN_TEXT **字号 16 非法**（真实库合法值域 {0,1,22,23,24,29,32,34,38,40,41}，最小 22，16 全库 0 条先例） | 钳制 ≥23（补丁 4 后 ≥29） |
| ② | outline 双向内缩 50 → 侧边引脚 L 连接线起点 py 悬空在框外；BGA 四边分布角部必然悬空 | outline x 内缩 50 / **y 外扩 50**；BGA 改**两侧多列** |
| ③ | **`X "MOCK_TEXT"` 是未知 X 指令类型**（真实库 X 指令只有 PIN_TEXT 64980 条/VHDL_PORT/HDL_PORT）→ 解析失败，报错定位到后续第一个引脚行（line 11 的 L） | `mock_text_cmd` 默认 X→P（Phase XX 又改 T） |

**验证**：63/63 mock cell 字号合法、1045 引脚 L 起点 0 悬空、40 mock 测试过。

### 5.3 SPCOCN-543（SIG_NAME/SPN 被删）——双根因

**用户报错**：`The pin property SIG_NAME with value GND_POWER\g has been deleted from the component GND_POWER` + 大量 SPN 被删（U18/U20/U3/U14/U6 系列）。

| 根因 | 修复 |
|------|------|
| ① GND_POWER LASTPIN offset 硬编码 golden **(50,100)**，但 fixture hdl_lib gnd_power 符号实际引脚 `C 0 50`（offset (0,50)）→ LASTPIN 未命中引脚 | routing.yaml/config.py 默认 `gnd_power_lastpin_offset=[0,50]` |
| ② p18 镜像场景：plumbing 电源符号被 rotate_point 镜像 → offset 翻成 (0,-50) 未命中；**Cadence 不镜像 plumbing** | `_is_plumbing_power(body_name)`：GND_POWER/VCC_CIRCLE **忽略 mirror** |

**验证**：全量 GND LASTPIN offset 均为 (0,50)、0 异常；测试断言更新（+26 过）。

### 5.4 SPCOCN-515（ORIGIN.SYM.1.1 缺失）

**现象**：双击 C481/C368（CAPACITOR）报缺 ORIGIN.SYM.1.1；_PH.SYM.1.1 库缺失（连锁 1158）。

**根因**：Cadence 打开带 part_table 符号时**隐式解析系统库 ORIGIN**；用户环境缺该库。输出包 0 处 ORIGIN 引用（grep 实锤非本转换器生成）。

**修复**：`output_manager.write_origin_lib()`——输出包**自包含 origin 库**（`origin/sym_1/symbol.css` + 目录结构）+ cds.lib `DEFINE origin origin`。

### 5.5 SPCOCN-542（默认属性 PACKAGE_TYPE 被删）——判定良性

### 5.7 SPN 机制与 LASTPIN 详解（Phase XIX 核心知识）

**SPN/SIG_NAME/$PN 是什么**：
- **LASTPIN** 是 CSA 里把"引脚属性"绑定到最近 FORCEADD 元件的机制；
- `FORCEPROP 3 LASTPIN (x y) SIG_NAME GND_POWER\g`——把 SIG_NAME 属性（网络名）绑到 (x,y) 处的引脚；
- `FORCEPROP 2 LASTPIN (x y) $PN C22`——绑引脚号；
- Cadence 校验 LASTPIN 坐标**必须落在 symbol 实际引脚位置**（C 指令坐标），否则**删除该属性并报 SPCOCN-543**。

**543 三处触发场景（全部已修）**：
1. LASTPIN offset 与符号引脚不匹配（GND_POWER (50,100) vs 实际 (0,50)）→ 默认改 [0,50]；
2. plumbing 电源符号被镜像（p18 场景）→ `_is_plumbing_power` 忽略 mirror；
3. mock cell 未加载（1158 连锁）→ 随 1158 修复解决。

**关键工程约束**：LASTPIN 坐标与 WIRE 端点**必须同源**（都来自 `_compute_pin_geometry` 的 pin_coords）——否则 Cadence 认为引脚无连接。OverlapResolver 移动 body 后必须重算 pin_coords（接线顺序铁律）。

## 7c. ★ Cadence symbol.css/CSA 指令字段规范（踩坑总结——新 Agent 必读）

> 以下字段位置全部经真实库 grep 实锤，**多轮 bug 的根源就是字段错位**。

### 7c.1 symbol.css 指令

**C 指令（引脚定义）**：`C x y "text" lx ly orient vis font type justify`
```
token:  C(0) x(1) y(2) "text"(3) lx(4) ly(5) orient(6) vis(7) font(8) type(9) justify(10)
例:     C -650 -700 "EE_CLK/C1_LED/FLOW" -675 -700 0 0 32 0 R
```
- **justify 是 token[10]**（R/L 字母，全库 65689 条只有 R/L——U/D 导致 parse error）；
- font 合法值域 `{0,1,22,23,24,29,32,34,38,40,41}`（**16 非法 → 1158**）；mock 钳制 ≥29；
- mock C 文本用**短引脚号**（框内 px+25 justify=L / px-25 justify=R）——与 X 长名分居。

**X 指令（引脚文本）**：`X "PIN_TEXT" "label" x y rot justify font ...`
```
token:  X(0) "PIN_TEXT"(1) "label"(2) x(3) y(4) rot(5) justify(6) font(7) ...
例:     X "PIN_TEXT" "AVDD/PLL" -590 250 0 0 24 0 0 0 0 0 1 0 0
```
- **justify 是 token[6]**（0=左对齐向右 / 1=右对齐向左）——**QA-9 根因：生成时写错位置恒 0**；
- **X 指令类型只有 PIN_TEXT（64980 条）/VHDL_PORT/HDL_PORT**——`X "MOCK_TEXT"` 非法（1158 第三根因）；
- mock：left/top 引脚 justify=1（框外向左）、right/bottom justify=0（框外向右）。

**T 指令（符号内文本）**：两行结构（指令行 + 文本行）
```
T x y xscale yscale font orient vis justify color(?) pen(?)
例:     T -89 -14 0.00 0.00 35 0 0 0 0 2 68
        MOCK
```
- 真实库字号可达 41/100/125；mock MOCK 标识用 **59 + c11=4**（标题栏 SIZE/DATE 醒目色先例）；
- **symbol 内 T 指令颜色受 Cadence 限制**（用户实测 c11=4 仍绿系）——纯红需属性标签方案（P2-6）。

**L 指令（引脚线）**：`L x1 y1 x2 y2 -1 0`——**起点 (x1,y1) 必须在 outline 边上**（1158 第二根因）；mock L 从 outline 边到引脚 tip。

**P 指令（属性声明）**：`P "NAME" "value" x y xscale yscale font ...`——容忍自定义属性名（X 是指令名必须已知）。PATH/PART_NAME 用 P。

**M 指令（矩形）**：`M x1 y1 x2 y2 -1 0`——outline 矩形（真实库大量使用）。

### 7c.2 CSA 指令

| 指令 | 用途 | 要点 |
|------|------|------|
| `FORCEADD <cell>..<section>` | 放置元件 | cell 名与 temp_lib 目录名大小写一致（515 库缺失） |
