## 3. 转换管线（Phase XXIII 态）

```
输入文件（EDF/DSN/CSV/PST*.dat）
    │
    ▼
Stage 1 Diagnose  ── DiagnosticPipeline.run() → DiagnosticReport
    │
    ▼
Stage 2 Parse     ── ParserRegistry（EDIF/DSN/CrossRef/pstxnet/pstchip）→ DesignIR
    │
    ▼
Stage 3 Scan      ── HDLLibScanner.scan() → ComponentDB（hdl_lib 扫描）
    │
    ▼
Stage 4 Match     ── MatcherPipeline.run_batch()（exact→fuzzy→feature→value→fallback）→ MatchResult
    │                + manual_matches（chip_config）+ power_ic_scorer
    ▼
Stage 5 Validate  ── ValidatorRegistry（Pin/NetName/PowerPin）→ DiagnosisError
    │
    ▼
Stage 6 Generate  ── WriterRegistry（cpm/cdslib/sch/csa/xcon/...）→ 输出文件 + 报告
```

**Phase XXIII 在 Stage 6 内的增强**（布线/输出层）：

```
Stage 6 内部细化：
  1. 匹配结果 → pin_coords（单源）
  2. 元件布局 → OverlapResolver.resolve_passives（防重叠，网格 50）
  3. 【T1 新增】ensure_gnd_symbols（--gnd-distribute 时页面 1/4 分块密度补点）
  4. 【T2 新增】apply_passive_orientation（--rotate-passives 时 R/L/FB 随连线旋转）
  5. 布线 route_nets（【T3 增强】trunk 避让 span 感知推离 + 冲突计数优先）
  6. 【T3 新增】trunk 无解回退标记 reason=trunk_blocked
  7. wire_simplify 后处理（默认关）
  8. 报告聚合 → aesthetic_report（三口径 + trunk_blocked/non_trunk 分项）
```

### 7.5 R-2 指标解读（用户询问详解）

**指标含义**：
```
[WIRE_THROUGH_BODY] detected=968 exempt=511 violations=457 (trunk_blocked=0, non_trunk=457)
```
- **detected=968**：转换检测到的**总穿体对数**（所有 WIRE 段穿过元件 outline 的次数）
- **exempt=511**：**豁免数**——自身引脚引出段（段端点=该元件引脚坐标，正常电气引出，reason=self-pin）+ 电源符号挂轨（电源网穿小体，reason=power_symbol）。这些不是违规
- **violations=457**：**真违规数**（detected - exempt）——穿**其他**元件体的段
- **trunk_blocked=0**：trunk 线上无违规——**R-2 的核心成果**：所有 trunk 线都成功避开了元件体（无"密集页无解回退直穿"）
- **non_trunk=457**：非 trunk 线上的穿体（全部）——多为 **stub 段**（引脚引出段穿其他元件体、电源网长 stub 穿大体），p0 三段式 stub 已避让但未全覆盖；完整绕障属 detour 布线器

**为什么"trunk 穿体=0"重要**：Phase XXII 时 violations=506 中有 283 条是**超长 trunk 竖直线**（如 seg=(-7800,5975,-7800,4050) 穿过 C8 body）——这是用户反馈"电线穿芯片/元件"的主因。R-2 通过 span 感知推离 + 冲突计数优先，让 trunk 线绕开所有元件体 → 这 283 条类穿体归 0。剩余 457 是 stub 段（短线段），视觉影响小且电气上往往不可避免（引脚在 outline 内引出必然穿一下，但已通过 exempt 规则排除自身引出；剩下的穿其他元件体的 stub 需 detour 完整绕障）。

**"WIRE 6492 不增反降"含义**：WIRE 段数从 Phase XXII 的 6708 降到 6492（-216）。初版三段式曾导致 WIRE +108%（10165，QA round-1 发现）→ 条件三段式收敛到 6708 → 本轮 trunk 避让优化后 trunk 坐标更优，反而减少了部分冗余段。**避让优化不增加布线复杂度**（不是"为了避让多绕路导致段数暴涨"）。
