## 二、当前匹配能力边界（实测代码行为）

### 2.1 `extract_pkg_size()` —— 只认 4 位数字封装

```python
_RE_PKG_SIZE = re.compile(r"(\d{4})")     # 只匹配 4 位连续数字！
_RE_BGA = re.compile(r"BGA\s*(\d+)")
_RE_SOT_QFN = re.compile(r"\b(SOT|QFN|MLF|TO-?\d+)")
```

**实测结果**：

| 输入 | 输出 | 判定 |
|------|------|------|
| `HSC0402-HDTB` | `0402` | ✅ 数字封装 |
| `SC0603-TD` | `0603` | ✅ 数字封装 |
| `0402C-S` | `0402` | ✅ 数字封装 |
| `SOD323` | `SOD323`（原样） | ❌ 字母封装无法归一化 |
| `SMA` | `SMA` | ❌ |
| `DO-214AC` | `DO-214AC` | ❌ |
| `SOT23` | `SOT` | ⚠️ 部分（仅首字母） |
| `LL-34` | `LL-34` | ❌ |
| `SOD2513X90N` | `2513` | ⚠️ 误提取为尺寸！ |
| `HSOD882` | `HSOD882` | ❌ |

**结论**：字母封装（SOD323/SMA/DO-214AC/LL-34/SOT23）无法与数字封装（0402/0603）归一化比较。
二极管库 ptf 的 PACKAGE_TYPE 全是字母（`SOD323`/`SMB`/`SMA`/`DO-214AC`/`SOT23`/`LL-34`/`SMC`/`TO252-1`），
CIS 侧是 `DZ_L_HSOD882_DZ_L` 等 → 尺寸匹配必然失败。

### 2.2 `normalize_value()` —— 只归一化数值（R/C/L 值）

```python
m = re.match(r"([\d.]+)([pnumk]?)F?", v, re.IGNORECASE)   # 电容
m = re.match(r"([\d.]+)([KM]?)", v, re.IGNORECASE)        # 电阻/电感
return v.upper()                                          # 兜底：原样大写
```

**实测结果**：

| 输入 | 输出 | 判定 |
|------|------|------|
| `10UF` | `10U` | ✅ 数值 |
| `100NF` | `100N` | ✅ 数值 |
| `4.7K` | `4.7K` | ✅ 数值 |
| `60UH` | `60U` | ✅（但 U 与 H 不区分单位） |
| `DZ_L` | `DZ_L` | ⚠️ 原样返回（非数值不归一化） |
| `DZ3` | `DZ3` | ⚠️ |
| `1N4148W-7-F` | `1N` | ❌ 严重误解析（把型号当数值） |
| `BAS21-03W` | `BAS21-03W` | ⚠️ 原样 |
| `LED` / `LB` / `UART` / `FILTER` | 原样大写 | ⚠️ |

**结论**：非数值标称值（二极管型号、芯片型号、功能名）无法与 HDL 库 ptf 的 VALUE 列
（`BAS21-03W`/`1N4148W-7-F`/`ES2B` 等型号）正确归一化比较。**更严重的是 `1N4148W-7-F`
被误解析为 `1N`** —— normalize_value 对带数字前缀的型号存在破坏性误匹配。

## 三、二极管匹配失败完整链路（D 系列）

```
CIS 侧（pstxprt.dat）: PART_NAME = 'DZ_L_HSOD882_DZ_L'  → value=DZ_L, footprint=HSOD882
HDL 库（diode/part.ptf）: PACKAGE_TYPE='SOD323', VALUE='BAS21-03W', JEDEC='SOD2513X90N'

PassiveMatcher L1（值+尺寸精确）:
  normalize(DZ_L)='DZ_L' vs ptf 'BAS21-03W' → 不等 → 失败
  extract_pkg_size(HSOD882)='HSOD882' vs 'SOD323' → 不等 → 失败
L2~L4 同样失败
L5 前缀兜底 → DIODE conf=0.38（type_only）
```

**根因三要素**：
1. CIS 值非数值（DZ_L/DZ3/空）→ 值无法匹配；
2. CIS footprint 字母封装（HSOD882）vs 库字母封装（SOD323）→ 无统一归一化；
3. 即使两边都是字母，extract_pkg_size 也无法提取可比对的特征码。

## 四、改进方案（按优先级）

### P0：`extract_pkg_size()` 增加字母封装归一化

为常见 SMD 封装建立标准归一化表，输出规范化的"封装等级代码"：

```python
_ALPHA_PKG = {
    "SOD323": "D-01", "SOD123": "D-02", "SMA": "D-03", "SMB": "D-04",
    "SMC": "D-05", "DO-214AC": "D-06", "DO-214AB": "D-07", "LL-34": "D-08",
    "SOT23": "S-01", "SOT223": "S-02", "SOT89": "S-03", "TO252": "S-04",
    "TO263": "S-05", "0402": "N-02", "0603": "N-03", "0201": "N-01", ...
}
```

- CIS 侧 `HSOD882`/`DZ_L_HSOD882` 应能提取 `SOD882` → 映射到尺寸等级；
- HDL 侧 `SOD323` → 同一等级体系；
- 附带好处：`_extract_size` 提取 `SOD2513X90N → 2513` 的误提取问题也需修复
  （字母封装不应走 4 位数字规则）。

### P0：`normalize_value()` 增加"非数值保护"

- 当输入以数字开头但后面跟非单位字母（如 `1N4148W-7-F`）时，不应按电容/电阻规则截断；
- 增加规则：`^\d+[A-Za-z]{2,}[0-9-]` 形态 → 视为型号（part number），整串大写比较，
  不参与数值归一化；
- 增加 `normalize_part_number()` 单独函数处理型号（去分隔符、统一大小写），
  用于 diode/IC/transistor 等非数值元件的 VALUE 匹配。

### P1：PassiveMatcher 增加"型号精确匹配层级"

在 L1 之前增加 L0：当 source 值非数值（normalize 后含字母型号特征）时，
直接与 ptf VALUE 做**型号精确匹配**（忽略大小写/分隔符），命中即 PASSIVE_EXACT。

### P1：ActiveMatcher 的 part_name 维度增强

- 已有 `part_name_aliases`（mj8→rj45），可扩展 diode 型号别名表（如 `1N4148→1N4148W-7-F`）；
- IC 匹配：CIS 值 `NT5CC256M16ER-EKI`（DDR 型号）与库 cell（如无 DDR cell）无法匹配
  是**库缺失**问题，非算法问题 —— 需扩展 HDL 库。

### P2：库侧改进

- `hdl_lib/diode` 的 ptf VALUE 已是型号（`BAS21-03W`），CIS 值若是真实型号（如 `1N4148W`），
  修复 normalize 后即可匹配；
- 但 CIS 值大量为 `DZ_L`/空 —— 这类**源数据本身缺值**，任何算法都无法凭空匹配，
  只能靠前缀兜底（当前 0.38 合理）或人工确认。

## 六、结论

1. **字母/字母数字混合封装（SOD323/SMA/DO-214AC 等）当前无法匹配** —— `extract_pkg_size`
   只认 4 位数字，需增加封装归一化表（P0）；
2. **非数值标称值（二极管型号/芯片型号/功能名）当前无法匹配** —— `normalize_value`
   对型号存在破坏性误解析（`1N4148W-7-F → 1N`），需增加型号保护与型号匹配层级（P0）；
3. **但注意**：HG5015 中大量 D* 元件的 CIS 值本身为空或 `DZ_L`（源数据缺值），
   **算法无法凭空匹配缺失的值** —— 这部分只能靠人工确认或源数据补全；
4. **U*/T*/LB* 的核心瓶颈是 HDL 库缺失**（无 DDR cell、无 60UH 变压器变体、磁珠值无特征），
   属库侧问题而非算法问题。
