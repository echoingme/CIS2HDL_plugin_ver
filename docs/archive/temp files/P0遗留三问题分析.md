> 对应 ROADMAP XI.6 遗留问题 1-3。

## 问题 1：25 个 ROUTE 跳线被错误跳过（889 vs 906 实例偏差根因）

### 现象
- con 输出 instances = 889，pstxnet 权威 refdes = 906（entire.csv 也是 906）
- 偏差 = 17，QA 定位 = U6 + 25 ROUTE J − 9 U6A-I section

### 根因（代码级）
- `cis2hdl/core/parser/component_catalog.py` L69: `"ROUTE": ""`（跳线：布线标记）
- L72-73: `_SKIP_REFDES_VALUES: set[str] = {"ROUTE"}`
- L227-233: Catalog 构建时 `if refdes.upper() in _SKIP_REFDES_VALUES or value.upper() in _SKIP_REFDES_VALUES: continue`

### 关键证据（实测）
- HG5015 CrossRef CSV：36 个 J 开头元件，其中 **25 个 Value="ROUTE"**（J8 J11 J12 J14 J15 J16 J17 J18 J19 J20 J21 J22 J23 J24 J29 J30 J31 J32 J33 J34 J35 J36 J37 J38 J47）
- entire.csv 中这 25 个：Source Package = ROUTE、PKG_TYPE = COPPER0201、Footprint = COPPER0201、VALUE = ROUTE、Type = ROUTE.Normal
- **pstxnet 中它们是真实元件**：J11 = 2 引脚（`2`→2P5GE_RSTN、`1`→HGPIO_17），J12 = 2P5GE_RSTN/HGPIO_17... 每个 2 引脚、连接两个不同网络
- entire.csv PININST：J11 NET1→HGPIO_17、NET2→2P5GE_RSTN

### 本质
OrCAD 中 **Value="ROUTE" + COPPER0201 封装 = 0 欧姆跳线**（零欧电阻 jumper，用于板级布线选项/跳线选择）。互联网调研确认（DigiKey RMCF0201ZT0R00 = RES 0 OHM JUMPER 0201）：
- 它是**真实元件**（2 引脚、连接两个网络），不是"布线标记"
- 板级通过"是否贴装该 0 欧电阻"决定网络桥接（如 J11 桥接 HGPIO_17 ↔ 2P5GE_RSTN）
- **跳线两端网络不同名**（不像普通电阻两端同网），转换后必须保留

### 解决方案（3 步）
1. **Catalog 不再跳过 Value="ROUTE"**：`_SKIP_REFDES_VALUES` 改为只跳过"无引脚/纯标记"（实测 ROUTE 都有 2 引脚，实际不存在纯标记场景；保守做法：移除 ROUTE 跳过，让 pstxnet 连接决定保留）
2. **映射到 hdl_lib cell**：检查 hdl_lib 是否有 jumper/0R 符号——若无，回退映射到 `resistor`（0 欧跳线本质是电阻）或新建 `route_jumper` 符号（2 引脚，引脚偏移 ±75 同电容）
3. **CSA/CSV 生成**：跳线按普通 2 引脚元件生成（LASTPIN $PN + SIG_NAME），两端不同网络名自然表达桥接

### 验证断言
- con instances == 906（== pstxnet refdes）
- con conn == 2821（== pstxnet 连接）
- 25 个 J 跳线在 con/csa/csv/cpc 中可见，每跳线 2 引脚连不同网络

## 问题 2：电源符号未进 csa/csv/cpc（与设计 C.5 不一致）

### 现象
- system_design.md C.5 约定：gnd_power/vcc_circle 进 csv/cpc(#ISCELL)/csa（FORCEADD + LASTPIN SIG_NAME），不进 con cells/instances
- QA 实测：当前输出 csa/csv/cpc 中**没有电源符号实体**——电源网数据完整（con scope=2、SIG_NAME 带 \g）但图纸上无 GND_POWER/VCC_CIRCLE 符号

### 根因
- csa_writer/csv_writer/cpc_writer 只遍历 `page.instances`（真实元件），未遍历电源网络生成电源符号
- 电源网（如 GND_POWER\g、DC12V\g）只有 con 里的 scope=2 登记和 SIG_NAME 标签，没有 FORCEADD 符号

### 为什么必须加（实测 + 调研）
- 真实工程 04p4 page9.csa：每个 GND_POWER 符号 = `FORCEADD GND_POWER..1 (x y);` + `FORCEPROP 3 LASTPIN (x y) SIG_NAME GND_POWER\g` + PATH/CDS_LIB/JEDEC_TYPE 等属性 + `HDL_POWER` 属性
- 真实工程 VCC_CIRCLE：`FORCEADD VCC_CIRCLE..1` + `FORCEPROP 3 LASTPIN SIG_NAME DC12V\g` + `FORCEPROP 1 LAST HDL_POWER DC12V`（**HDL_POWER 属性 = 网络名关联，形状无所谓**，调研确认）
- csv：`%"GND_POWER"` + `"1","(x,y)","0","hdl_lib","I27";` + HDL_POWER 属性 + `"GND"<netId>;`（单引脚格式）
- cpc：`#ISCELL hdl_lib gnd_power * page14_i1`（ISCELL = 虚拟元件）
- **Cadence 文档**：DEHDL 的电源符号关键属性是 HDL_POWER（= 网络名）；电源符号不进 con cells/instances（8367 实测）

### 解决方案
1. **电源网识别**：从 pin_connections 找出电源网（网络名匹配 GND/VCC/VDD/DC3.3V/12V0 等电源模式 + \g 全局后缀；或 pstxnet 中该网所有引脚都是电源引脚）
2. **CSA 生成**：每页每个电源网放 1 个电源符号（GND 用 GND_POWER、电源用 VCC_CIRCLE），坐标放页面边缘（或该网第一个引脚附近），生成 FORCEADD + LASTPIN SIG_NAME(\g) + HDL_POWER
3. **CSV 生成**：对应单引脚块（HDL_POWER + `"GND"<netId>;`）
4. **CPC 生成**：#ISCELL 条目
5. **CON 不变**：电源符号不进 con cells/instances（保持 C.5 约定）

### 验证断言
- 每个电源网在每页 csa 有 FORCEADD GND_POWER/VCC_CIRCLE
- csv 有对应 %块 + HDL_POWER
- cpc 有 #ISCELL gnd_power/vcc_circle
- con 无电源符号（保持）

## 问题 3：自动网名未转 UN$ 形式

### 现象
- OrCAD EDIF 自动网名如 `$47N777`、`$50N80178`（$ 开头的内部网名）
- 当前 con_name() 转成 `47n777`（数字开头）、`50n80178`——**数字开头 + 无 UN$ 语义**，Cadence 校验风险
- 真实 Cadence 工程（8367）自动网名：`UN$1$CAPACITOR$I12$1`（UN$ + 页号 + $ + CELL + $ + I<k> + $ + 引脚号），con 内部名 = `unnamed_1_capacitor_i12_1`

### 根因
- `net_utils.py` 的 auto_net_name() 未实现或未接线：`$47N777` 这类网名没有按"连接该网的 refdes+pin"推导 UN$ 结构
- con_writer 直接用了 con_name() 的简单清洗（$→去掉），没触发 auto_net_name

### UN$ 命名规则（8367 实测）
```
格式: UN$<页号>$<CELL>$<I<k>>$<引脚号>
样例: UN$1$CAPACITOR$I12$1  → con 内部名 unnamed_1_capacitor_i12_1
     UN$1$DC_DC$I1$EN      → unnamed_1_dc_dc_i1_en
```
- 页号 = 物理页码
- CELL = 元件符号名（大写，如 CAPACITOR）
- I<k> = 页内实例编号（与 cpc/csv 的 I<k> 一致）
- 引脚号 = 连接该网的那个引脚

### 解决方案
1. **net_utils.auto_net_name(refdes, pin, page, cell, inst_k)**：生成 UN$ 格式 + 内部 unnamed_ 格式
2. **con_writer/csv_writer 触发**：当网络名为自动网（$ 开头、或 UN$ 开头）时，用该网第一个连接（refdes+pin）推导 UN$ 名
3. **双向转换**：UN$X$Y$Z$W ↔ unnamed_x_y_z_w（con 内部名用下划线替代 $）

### 验证断言
- con 中无数字开头网名（全部转 unnamed_ 格式）
- csv 中无 $47N777 样式（显示名 UN$1$CAPACITOR$I12$1）
- SIG_NAME 标签与 csv 显示名一致

## 附：8367 数据来源混用检查结论

用户要求确认"是否有数据来自 HG5015 却分析了 8367 导致不匹配"。结论：
- **代码中 8367 只出现在注释/示例**（output_manager.py docstring、config.py 注释），无硬编码数据
- system_design.md 格式模板来自 8367/04p4 逆向——**格式规则是通用参考**，实现时用 HG5015 实际数据填充
- 唯一"8367 影响 HG5015"的点：**con 的电源页局部网（pageN_ 前缀）模式**照搬 8367（8367 有 page1_gnd_power 局部网 + gnd_power 全局网双登记），HG5015 的 97 个 pageN_ 局部网是否必要待 Cadence 实测确认（8376 模式与 HG5015 电源网分布不同）
- **结论：无数据混用导致的错误**，格式规则可通用，但"电源页局部网"数量应随 HG5015 实际数据自适应（当前 97 个 = 按页按电源网生成，合理）
