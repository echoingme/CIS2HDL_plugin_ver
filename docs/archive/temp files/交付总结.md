## 关键结论速览

1. **工程结构合法**（cpm/cds.lib/xcon/con/dcf 齐全，16.6 可打开），889 元件全部写入。
2. **网络连接严重缺失**：con 510 net/1466 instTerm vs pstxnet 源 590 net/2821 连接 → 约 48% 连接丢失。
3. **根因**：pstxnet_netlist_parser.py 状态机缺少 RATSNEST_SCHEDULE/NET_PHYSICAL_TYPE/NET_SPACING_TYPE 跳过规则，GND(845)/12V0(49) 等网络整块丢失。
4. **修复已验证**：在 `_RE_SKIP_LINE`（L74-76）增加 3 个关键字后，连接数 1818→2806（恢复 99.5%），GND/12V0 100% 恢复。
5. **CSA 无任何连线**（PAINT WIRE 已移除且无 SIGNAL 标签），原理图打开只有孤立元件。
6. **PCB 库缺口**：154 个 hdl_lib 目录仅 2 个含 .psm/.pad/.dra → 即使网表完整也无法进 Allegro 布局。
7. **网表导出不充分**：Packager-XL 依赖 con，con 不完整 → pstx 三件套必然缺网。
8. **Allegro 显示连线**：官方链路 = DEHDL → Packager-XL → pstx 三件套 → Import Logic → ratsnest；OpenAllegroParser 只解析 PCB 二进制（.brd/.pad/.psm），不适用。
9. **非数值匹配**：extract_pkg_size 只认 4 位数字封装；normalize_value 对型号有破坏性误解析（1N4148W-7-F→1N）。D* 低置信度根因 = 值缺失 + 字母封装 + 库不匹配三重叠加。

### 架构师（高见远）补充结论

- **网络丢失三大根因**：① pstxnet 状态机漏 4 类属性行（含 RELATIVE_PROPAGATION_DELAY）→ 41 网络清空、1003 连接丢；② U6 母 refdes↔分 section 失配 → 主 SoC 连接全丢 + 35 网络消失；③ EDIF rename/joined 未解包 → 99.2% 空网络名，注入形同虚设
- **3717 是假指标**：DSN 每页 net 累计（含空/重复），matched_nets = min(nets,nets)
- **HDL 可用性评级 D**：con/xcon/csa 三者格式与参考 8367 工程不兼容，不满足网表导出充分条件
- **Part C**：OpenAllegroParser 只解析 Allegro 二进制不可用；**方案 b（透传原始 pstx 三件套）性价比最高**，可立刻让 Allegro 显示连线
