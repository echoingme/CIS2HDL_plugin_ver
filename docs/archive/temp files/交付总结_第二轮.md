## 二、核心方案（架构师报告 + 总监验证）

### CSA 连线四条命令
```
WIRE 16 -1 (x1 y1)(x2 y2);              ← 导线（几何重合建立连接）
DOT 1 (x y);                             ← 连接点
FORCEPROP N LASTPIN (x y) $PN <n>        ← 引脚位置+号
FORCEPROP N LASTPIN (x y) SIG_NAME <net> ← 引脚网络名
```

### 跨页连接两种方式
| 方式 | 符号 | 机制 |
|------|------|------|
| 电源/地 | GND_POWER/VCC_CIRCLE（standard） | SIG_NAME xxx\g（全局信号） |
| 普通信号 | IOPORT/INPORT/OUTPORT（standard） | 同名网络自动跨页合并 |

### ★ 最严重：con 不是 Cadence 格式
真实：`("S2" "dc_dc" "hdl_lib" "sym_1" (terms...))` + `("N2" "net" -1 -1 0)` + `("I1" ... (pins (conn ...)))`
我们：(cell/cell)+(net+instTerm)+(instance+loc) → Packager-XL 无法读取 → **100% 网络转换 + 网表导出的头号障碍**

### 缺口文件清单
pageN.csa（缺 LASTPIN/WIRE/DOT/IOPORT）、pageN.csv（完全不生成）、pageN.cpc（缺实例）、
5015.con（格式重写）、5015.xcon（填充）、cds.lib（缺 standard）、hdl_lib（缺 port 符号）

### 代码层根因（6 处）
edif_parser（2771 注入未 merge）、csa_writer（不写连线）、output_manager（con/xcon 自创格式）、
dsn_parser（off_pages 丢弃）、网络名清洗（$xxx/&xxx→合法 + 电源 \g）

## 工程师（寇豆码）根因核实结论

### 1. page.map 页码错位（P1 高）
- `write_page_map()`（output_manager.py L666-671）用 `enumerate(pages)` 的 idx 当页码写第一列
  → 产出 `1 1 16-WIFI2G`（应为 `16 16 16-WIFI2G`）
- DSN 解析顺序 ≠ 页码顺序（dsn_parser._read_all_pages 无排序，16-WIFI2G 在前）
- master.tag/xcon/cpc 编号均正确，**唯一错位就是 page.map 第一列**
- 修复：复用 `_extract_page_number`（page_name 前缀取数字）+ 按页码排序

### 2. SPCOCN-542 规律（P2 中）
- 只删 symbol.css **未声明**为默认属性的 FORCEPROP 属性
  - capacitor/resistor 声明全套 → 不报错；ch347 缺 PART_NAME/PATH → 部分删；rf_sw/rj45 几乎未声明 → 四项全删
- 参考工程单 section 写 `$LOCATION`（带 $），我们写 `LOCATION`（无 $）→ 不合惯例
- 修复：① 库侧补 ch347/rf_sw/rj45_2x2_led symbol.css 默认属性声明；② csa_writer L433-456 改 $LOCATION

### 3. J47/厚膜 + 跨页连接符（P3 低）
- J47/PWC3_A = 库缺失（output_v2c/tests hdl_lib 均无），用户已说可不处理
- 跨页连接符 = 代码未实现：dsn/page_parser L118 解析了 ports、PageIR 有字段，但 csa_writer 从未使用 → 单独立项
