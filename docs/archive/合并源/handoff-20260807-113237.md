## 2. v1.0 MultiScorer 问题诊断

### 2.1 架构缺陷

v1.0 引入了 `MultiScorer` 六维加权全库打分（移除前缀硬约束），导致：

| 问题 | 严重度 | 根因 |
|------|:---:|------|
| 电容→电阻/电感跨类型匹配 | 🔴 | prefix 权重仅 0.20，被 footprint+pin_count (0.45) 淹没 |
| conf 虚高 | 🔴 | `max(Fallback.conf, MultiScorer.score)` 取两套系统最大值 |
| ValueMatcher 无类型检查 | 🔴 | 找到唯一值匹配就 conf=1.0，不管候选是电阻还是电容 |
| pin_count 无区分力 | 🟡 | 所有无源器件 2 脚，该维度完全浪费 |
| correlations.yaml 污染 | 🟡 | 积累了 17 个 v1.0 跨类型错误学习记录 |

### 2.2 conf 机制问题

```
v1.0: result.confidence = max(matcher_chain_confidence, MultiScorer_score)
      → 电容 C11 匹配到电阻 resistor，conf=1.0（完全错误！）

v2.0: result.confidence = phase1_prior_conf × phase2_within_conf
      → 同例：phase1=1.0 (C→capacitor) × phase2=0.80 (value match) = 0.80
```

### 2.3 典型错误案例

| 案例 | v1.0 匹配 | v1.0 conf | 实际类型 | 问题 |
|------|-----------|:---:|------|------|
| C11 (1mF) | resistor | 100% | capacitor | 致命类型错误 |
| C21 (22UF) | inductor | 70% | capacitor | 致命类型错误 |
| C282 (22UF) | inductor | 70% | capacitor | 致命类型错误 |
| D21 (0) | resistor | 100% | diode | 致命类型错误 |
| R2 (100K) | capacitor | 60% | resistor | 致命类型错误 |
| M1 (MARK) | rtxm169 | 50% | mark | 完全无关 |
| LB4 (LB) | ch347 | 50% | ferrite_bead | 完全无关 |

详见：`docs/MATCHING_ANALYSIS_2026-08-06.md`

## 3. v2.0 两阶段匹配架构

### 3.1 架构总览

```
Phase 1: TYPE HYPOTHESES (类型假设排序 — 不锁死)
  refdes前缀 + PST数据 + 值特征 + 学习矩阵
  → 有序类型假设列表 [(type, prior_conf), ...]

Phase 1.5: CANDIDATE POOL CONSTRUCTION (按类型构建候选池)
  按类型假设顺序构建搜索池，去重

Phase 2A: PASSIVE MATCHER (被动元件确定性规则)
  适用于: C(capacitor), R(resistor), L(inductor), D(diode/zener)
  5 级递进: 值+尺寸双精确 → 值精确 → 尺寸近似 → 尺寸兜底 → 前缀兜底

Phase 2B: ACTIVE MATCHER (主动元件类型内评分)
  适用于: IC, connector, crystal, switch, transformer...
  5 维类型内加权评分 (不含 prefix 维度)

法 Final conf = phase1_prior × phase2_within (乘法，不取 max)
```

### 3.2 Phase 1 — TypeHypothesisGenerator

**文件**: `cis2hdl/core/matcher/type_hypothesis.py` (178行, NEW)

**配置来源**: `cis2hdl/config/type_gate.yaml` (86行, NEW)

**处理流程**:
```
Step A: _from_yaml(prefix) — 读取 type_gate.yaml 的先验概率
Step B: _apply_pst_boost() — PST JEDEC_TYPE 确认时提升对应类型先验
Step C: _apply_value_hints() — 值特征辅助 (NH→inductor, MHz→crystal 等)
Step D: _apply_learned_affinity() — 历史学习矩阵调整 (仅提升，不降低)
Step E: _normalise() — 归一化 + 排序
```

**关键设计决策**: 
- Phase 1 不做单一锁死，输出有序列表而非单一类型
- `_apply_learned_affinity` 仅在 learned > prior 时触发混合（防止 IC:0.85 被 learned:0.10 拖低到 0.625）
- 歧义前缀维护多类型假设（如 U→[IC:0.85, interface:0.70, connector:0.40]）

**示例输出**:
```
C89 → [(capacitor, 1.0)]
U7+FPGA → [(ic, 0.95), (interface, 0.70), (connector, 0.40)]
D21(0) → [(diode, 0.95), (zener, 0.85), (tvs, 0.65)]
LB4 → [(ferrite_bead, 0.75), (inductor, 0.50)]
RD25 → [(resistor, 0.90)]
```

### 3.3 Phase 1.5 — CandidatePoolBuilder

**文件**: `cis2hdl/core/matcher/candidate_pool.py` (120行, NEW)

**功能**: 按类型假设构建候选池，支持四重过滤：
1. `candidate.category` 类型匹配（大小写不敏感）
2. `candidate.phys_des_prefix` 映射匹配（通过 `_PHYS_DES_TO_TYPE` 字典）
3. `candidate.part_name` 包含类型名
4. `candidate.library_id` 路径包含类型名

**_PHYS_DES_TO_TYPE 映射表**（关键修复：17 个物理前缀→类型映射）:
```
ic→ic, u→ic, xs→connector, j→connector, h→connector,
tp→test_point, sw→switch, osc→oscillator, et→transformer,
th→inductor, k→relay, q→transistor, fb→ferrite_bead, ...
```

### 3.4 Phase 2A — PassiveMatcher

**文件**: `cis2hdl/core/matcher/passive_matcher.py` (209行, NEW)

**5 级确定性规则**（不接受权重妥协）:

| 级别 | 条件 | 策略 | conf |
|------|------|------|:---:|
| L1 | 值精确 + 尺寸精确匹配 | PASSIVE_EXACT | 1.00 |
| L1b | 值+尺寸精确，多候选→JEDEC tiebreak | PASSIVE_EXACT_MULTI | 0.95 |
| L2 | 值精确，CIS footprint 缺失/无效 | PASSIVE_VALUE_ONLY | 0.80 |
| L3 | 值精确，尺寸不匹配但存在近似 | PASSIVE_VALUE_NEAR | 0.70 |
| L4 | 尺寸精确，值不匹配 | PASSIVE_SIZE_ONLY | 0.60 |
| L5 | 仅前缀类型匹配 | PASSIVE_PREFIX_ONLY | 0.40 |

**v2.0 关键增强**:
- L2 在 CIS footprint 为空或为类别名（"capacitor"/"resistor"）时触发
- L2 检测到 JEDEC 提供有效尺寸时跳过，让 L3 进行真实的尺寸比较
- L1/L3 使用 CIS JEDEC_TYPE (如 SC0603-TD→0603) 作为 footprint fallback
- 所有层级使用 `normalize_value()` 进行值比较，`extract_pkg_size()` 提取尺寸

### 3.5 Phase 2B — ActiveMatcher

**文件**: `cis2hdl/core/matcher/active_matcher.py` (169行, NEW)

**5 维类型内加权评分**:
```
footprint:  0.30  封装尺寸比较
value:      0.15  值比较
jedec:      0.20  JEDEC_TYPE 匹配
pin_count:  0.20  引脚数接近度
part_name:  0.15  部件名称重叠
```

**匹配器链**: Exact → Fuzzy → Feature → Value → Fallback（在类型内运行）

**v2.0 关键修复**: chain 返回 Fallback 时，优先使用 top-scored 候选（而非 Fallback 选中的前缀匹配候选）

### 3.6 MatcherPipeline 重构

**文件**: `cis2hdl/core/matcher/pipeline.py` (修改, run_batch 完全重写)

**新流程**:
```python
for source in sources:
    # Phase 1: 类型假设
    hypotheses = type_gen.generate(refdes, value, pst_data)
    
    # Phase 1.5: 候选池构建
    pool = pool_builder.build(hypotheses)
    
    # Phase 2: 搜索
    for type_set in pool.iter_in_priority_order():
        if type in PASSIVE_TYPES:
            result = passive_matcher.match(source, candidates, type)
        else:
            result = active_matcher.match(source, candidates, type)
        
        final_conf = type_set.prior_conf × result.confidence
        
        # 停止条件:
        if is_passive_exact:           break  # L1 精确匹配
        if is_fixed_prefix:            break  # LB→ferrite_bead 强绑定
        if final_conf >= 0.75:         break  # 高置信度
    
    # 后处理: 生成 Top-3，记录学习
```

**关键阈值**:
- `STOP_SEARCH_THRESHOLD`: 0.75 (达到即停止搜索)
- `NEEDS_REVIEW_THRESHOLD`: 0.40 (低于此值标记需人工确认)
- `PASSIVE_EXACT`: 立即停止（conf=1.0）
- `fixed_prefixes`: 强绑定停止（LB→ferrite_bead, LED→led, TP→test_point, FB→ferrite_bead）

## 5. JEDEC→footprint 数据链路

### 5.1 标准命名约定（Web 搜索确认）

| CIS JEDEC | 含义 | 提取尺寸 |
|-----------|------|:---:|

### 5.2 数据流路径（6 步）

```
Step 1: pstchip.dat 解析
  PstchipParser.parse() → dict[str, PstchipEntry]
  格式: {'C_SC0603-TD_10UF': PstchipEntry(jedec_type='SC0603-TD', value='10uF')}

Step 2: PST xprt→pstchip 查找桥
  PstxnetParser.build_pstchip_lookup() → dict[refdes, PstchipEntry]
  880 个 refdes 完成映射

Step 3: InstanceIR 注入（Stage 2.5b, conversion_engine.py:1376）
  _inst.extra_data["pst_jedec_type"] = chip_entry.jedec_type
  → 880/889 实例注入成功

Step 4: ComponentDef 注入（Stage 4 _stage_match, conversion_engine.py:883-902）
  _comp.extra_data["jedec_type"] = inst.pst_jedec_type
  → 880/889 ComponentDef 注入成功

Step 5: PassiveMatcher 提取（L1/L2/L3）
  extract_pkg_size(source.extra_data.get("jedec_type",""))
  → "SC0603-TD" → "0603"

Step 6: 尺寸匹配
  src_fp_size("0603") vs PTF row jedec_type/packaging
  → 匹配成功 → PASSIVE_EXACT (conf=1.0)
```

### 5.3 关键修复点

**Bug 10（conversion_engine.py:883）**:
```python

# → 跳过了 _extract_cis_components 中的 JEDEC 注入代码

# 修复后: catalog 路径后追加注入
```

## 12. 关键设计决策

1. **Phase 1 类型假设排序而非锁死** — 维护有序类型列表，多类型并行搜索，最终由候选质量决定归属

2. **被动元件 = 确定性规则，主动元件 = 类型内评分** — 拒绝跨类型权重妥协

3. **conf = Phase1_prior × Phase2_within** — 乘法而非取 max，真实反映两层可信度

4. **JEDEC_TYPE 作为 footprint fallback** — CIS JEDEC 包含标准化封装尺寸（SC0603-TD→0603），用于 PassiveMatcher 精确匹配

5. **固定前缀强绑定** — LB/LED/TP/FB 等物理含义明确的前缀，首个类型假设不再降级

6. **PST data flow 完整打通** — pstchip→InstanceIR→ComponentDef→PassiveMatcher 数据链路

7. **学习矩阵仅提升不降低** — PrefixAffinityCalculator 在 Phase 1 中仅对高于先验的学习结果触发混合

8. **保持 MatcherBase/Registry 接口不变** — 新 PassiveMatcher/ActiveMatcher 继承 MatcherBase，兼容现有匹配器链
