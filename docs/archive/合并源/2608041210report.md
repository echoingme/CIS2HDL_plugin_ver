## 二、已完成的功能和算法

### 2.1 CFB 容器读取 (`cis2hdl/core/parser/dsn/ole_reader.py`)

**OleReader 类** — MS-CFB 复合文件读取器，约 610 行。

核心方法：
| 方法 | 功能 |
|------|------|
| `_parse_header()` | 解析 CFB 512 字节头部（魔数、FAT、目录扇区） |
| `_build_fat()` | 从 DIFAT 条目构建完整 FAT 链表 |
| `_read_directories()` | 解析目录条目（128字节/条），尝试 +1 sector OrCAD 变体偏移 |
| `_visit_dir()` | Red-Black Tree 中序遍历，构建层级路径 |
| `list_all_entries()` | 返回树遍历的 `OlePathEntry` 列表 |
| `list_raw_dir_entries()` | 返回所有非空 DirEntry，不依赖 RB-tree |
| `count_page_candidates()` | **新增** — 统计 raw entries 中页面候选流（匹配 PAGE/VRTL/`^\d{2,3}-` 模式） |
| `read_stream_by_path()` | 按层级路径读取流 |
| `read_stream_from_entry()` | 直接从 OlePathEntry 读取，绕过树 |
| `_get_sector_chain()` | FAT 链遍历，处理 0xFFFFFFFD（contiguous）OrCAD 变体 |

**关键算法 — count_page_candidates()**：
```python
# 4 条匹配规则
1. name_upper.startswith("PAGE")
2. "VRTL" in name_upper
3. re.match(r'^\d{2,3}-', entry.name)  # "01-Cover_Page" 等
4. stream_size > 2000 且不在系统流名称中
```

### 2.2 Library 流 strLst 解析 (`cis2hdl/core/parser/dsn/library_parser.py`)

**新建文件**，约 90 行。解析 Library CFB 流的字符串表。

**`parse_strlst(library_bytes) → list[str]`** 算法：

```
1. skip(48)  — 跳过 header (introduction + version + timestamps)
2. text_font_len = read_uint16()
3. skip((text_font_len - 1) * 60)  — 跳过 LOGFONTA 结构体（60字节/个）
4. some_len = read_uint16()
5. skip(some_len * 2)  — 跳过 some_data
6. skip(8)  — 跳过 unknown
7. 跳过 8 个 part field strings（uint16 len + len bytes + 0x00）
8. skip(156)  — 跳过 PageSettings
9. str_lst_len = read_uint32()
10. 逐条读取：uint16 slen + slen bytes Latin-1 + 0x00
11. GBK 回退：如果 Latin-1 结果中非可打印字符 > 20%，尝试 raw.decode("gbk")
```

**HG5015 结果**: 5490 条 strLst 条目。

### 2.3 Cache 流解析 (`cis2hdl/core/parser/dsn/cache_parser.py`)

**新建文件**，约 320 行。从 Cache 流提取 Package/LibraryPart/Device 元件定义。

**`parse_cache_stream(cache_bytes) → CacheParsedData`** 算法：

```
1. skip(4) — Cache header (0x0000 + unknown uint16)
2. 循环 parse_cache_entry() 直到 EOF
3. 如果 sequential 解析失败 → 暴力 preamble 扫描恢复

Cache Entry 格式：
  - Variable metadata (3 variants, probe detection)
  - Twin ID check (id0 vs id1, uint32×2)
  - 若不匹配 → 子循环 (package names + source library paths)
  - Structure header (some_id0 + some_id1 + struct_type uint16)
  - Standard prefix chain + preamble + structure body
```

**关键陷阱**：Cache 流所有字符串使用 **uint16 长度前缀**（不是 uint32！）。`read_string_len_zero_term()`（uint32）会因 0x00 高字节截断字符串。

**HG5015 结果**: 39 packages, 47 components 提取到 component_db。

### 2.4 DSN 页面解析 (`cis2hdl/core/parser/dsn/dsn_parser.py` + `page_parser.py` + `structures.py`)

**DSNParser.parse() 管道**：
```
OleReader → strLst 加载 → Cache 解析 → 页面流发现 → 页面解析 → 
层次块展开 → IR 构建 → EDIF 类型映射
```

**页面流发现 (`_read_all_pages()`)**：
- 主路径：CFB 树中 `Pages/` 下流条目
- 回退路径：当 `len(pages) < ole.count_page_candidates()` 时，扫描 raw entries
- 回退匹配规则：PAGE 前缀 / VRTL 包含 / `^\d{2,3}-` 编号模式

**页面二进制解析**：
- `parse_page(buffer, page_id, strlst)` — 基于 preamble 扫描的解析
- 支持的 StructureType：Page(10), PlacedInstance(13), T0x10(16), Wire(20/21), Port(23), Global(37), OffPageConnector(38), Alias(49), SymbolDisplayProp(39) 等
- 不支持的：TitleBlock(64/65), T0x34(52), T0x35(53), GraphicInsts

**PlacedInstance 解析**：
- 标准格式：`_parse_placed_instance_standard()` — 内联字符串读取（uint16 长度前缀）
- RTL 格式：`_parse_placed_instance_rtl()` — strLst 索引解析（uint16 值 > 200 时为索引）
- 虚假实例过滤：`db_id == 0` 的实例跳过

### 3.2 核心问题：匹配成功率 39%

**3 层根因**：

1. **DSN RTL 格式解析缺陷**：`_parse_placed_instance_rtl()` 从 strLst 解析的 pkg_name 产生大量虚假 library_id（如 "10868", "DDRC_A8", "INS1097" 等网络名/引脚名/数字ID），与 Cache 中真实库名无法对应。

2. **component_db 仅含 47 个元件**：Cache 解析器仅能提取 Package 结构体（LibraryPart 解析因长前缀 boundary 定义不充分而全部失败），远不足以覆盖 993 个实例。

3. **ExactMatcher 指纹不可用**：大部分 DSN 实例的 `properties` 字典为空（prefix_props 的 strLst 索引解析不完善），导致 ComponentDef 的指纹始终为 `"||0"`，无法匹配 HDL 库。

### 3.3 已知限制

| 问题 | 详细 | 优先级 |
|------|------|:--:|
| LibraryPart 解析失败 | Cache 流中长前缀 byte_offset boundary 不足以覆盖图元段 | P0 |
| strLst 前缀 props 解析 | prefix_props 的 name_idx/val_idx 与 strLst 的对应关系有误 | P0 |
| HG5015 页面流格式变体 | 页面流中的 PlacedInstance 使用不同于标准 OrCAD 的二进制格式 | P0 |
| 坐标重叠 (0,0) | 591/993 实例坐标为零，需改进 RTL 坐标提取 | P1 |

## 五、下一步建议

### P0 — 关键修复

1. **修复 strLst 前缀 props 解析**：`structures.py:auto_read_prefixes()` 中的 `name_idx/val_idx` 需要正确对应 strLst 条目。当前 prefix_props 使用 `read_string_byte_len()` 读内联字符串而非 strLst 索引，导致 properties 为空。

2. **修复 LibraryPart 解析**：`cache_parser.py` 中长前缀的 byte_offset boundary 需要扩展以覆盖图元段。参考 `OpenOrCadParser:StreamCache.cpp` 中的边界处理。

3. **HG5015 页面流变体适配**：页面流中 PlacedInstance 的二进制格式与标准 OrCAD 不同。需要通过 hex dump 分析确定正确的偏移量和字段布局。

### P1 — 增强功能

4. **EDIF 属性反注增强**：扩展 `_map_edif_types_to_dsn()` 填充 footprint/value/pin_count，使 ExactMatcher 指纹可用。

5. **信息页 page_parser 修复**：Cover_Page/Clock_Tree/Power_Tree 的 preamble 扫描失败，需实现顺序流布局解析。参考 `OpenOrCadParser:StreamPage.cpp`。

6. **坐标提取改进**：修复 RTL 格式中的坐标读取（当前 591/993 为零）。

### P2 — 可选优化

7. **DrawnInst 层次遍历验证**：`_resolve_hierarchy()` 已实现但未在 HG5015 数据上充分验证。

8. **BISHEET 端口 CSA 输出**：层级端口的图形元素映射到 CSA 格式。
